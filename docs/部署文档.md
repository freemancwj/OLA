# WaterCloud 教学管理系统 · 部署文档

> 适用版本：`ProjectVersion 1.0.7`（.NET 6 主站 + .NET 8 聊天服务）
> 本文档覆盖：本机已完成的 IIS / Nginx 两种部署、四种数据库的初始化、以及发布到远程服务器的标准流程。

## 四、数据库准备（四选一）

主站配置项在 `appsettings.json` 的 `SystemConfig` 节点：

```jsonc
"DBProvider": "SqlServer",            // SqlServer / MySql / PostgreSQL / Sqlite
"DBConnectionString": "…",
"AutoCreateTable": false              // 空库首次初始化时可置 true，建表完成后务必改回 false
```

### 4.1 SQL Server（推荐）

```sql
-- 1) 还原备份（按实际数据目录调整 MOVE 路径）
RESTORE DATABASE watercloudnetdb
FROM DISK = N'D:\deploy\database\sqlserver\watercloudnetdb.bak'
WITH REPLACE,
     MOVE 'watercloudnetdb'     TO N'D:\Data\watercloudnetdb.mdf',
     MOVE 'watercloudnetdb_log' TO N'D:\Data\watercloudnetdb_log.ldf';
```

```jsonc
"DBProvider": "SqlServer",
"DBConnectionString": "Data Source=.;Initial Catalog=watercloudnetdb;User ID=sa;Password=cwj;TrustServerCertificate=True;Encrypt=False"
```

### 4.2 MySQL

```powershell
mysql -u root -p -e "CREATE DATABASE watercloudnetdb CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
mysql -u root -p watercloudnetdb < .\database\mysql\watercloudnetdb_mysql.sql
```

```jsonc
"DBProvider": "MySql",
"DBConnectionString": "Server=localhost;Port=3306;Database=watercloudnetdb;User=root;Password=1qazZAQ!;CharSet=utf8mb4;AllowLoadLocalInfile=true"
```

> MySQL 注意：TEXT/BLOB 不能作主键，代码已把未声明类型的字符串主键兜底为 `varchar(50)`。

### 4.3 PostgreSQL

```powershell
# 用 psql 执行（PowerShell 下先设置 PGPASSWORD 可免交互）
$env:PGPASSWORD='cwj'
psql -U postgres -c "CREATE DATABASE watercloudnetdb ENCODING 'UTF8';"
psql -U postgres -d watercloudnetdb -f .\database\postgresql\watercloudnetdb_pg.sql
```

```jsonc
"DBProvider": "PostgreSQL",
"DBConnectionString": "Host=localhost;Port=5432;Database=watercloudnetdb;Username=postgres;Password=cwj"
```

> PostgreSQL 注意：表中标识符统一小写；若只用空库首次启动，可置 `AutoCreateTable=true` 让程序按实体自动建表（建完改回 `false`）。

### 4.4 SQLite

把数据文件复制到站点根目录（与 `WaterCloud.Web.dll` 同级）：

```powershell
Copy-Item .\database\sqlite\watercloudnetdb_sqlite.db .\publish\watercloudnetdb_sqlite.db
```

```jsonc
"DBProvider": "Sqlite",
"DBConnectionString": "DataSource=./watercloudnetdb_sqlite.db"
```

> SQLite 适合单机演示；高并发写入场景建议 SQL Server / MySQL / PostgreSQL。应用程序池需要对站点目录有写权限（数据库文件会被写入）。

### 4.5 切换数据库的两种方式

1. 直接覆盖配置：把 `deploy/config/appsettings.<数据库>.json` 复制为 `publish/appsettings.json`，修改连接串后重启站点。
2. 只改 `DBProvider` 与 `DBConnectionString` 两行（推荐），修改后**必须重启** IIS 应用程序池或 Kestrel 进程。

> `deploy/config` 中的配置变体已移除 `"urls"` 项，以便 IIS `inprocess` 托管时由 IIS 分配端口；若用 Kestrel 直接运行，请通过启动参数指定监听地址，例如 `dotnet WaterCloud.Web.dll --urls http://127.0.0.1:5005`。
> 聊天服务（`publish-chat/appsettings.json`）的 `Database.Provider` 也必须改成同一种数据库，且数据库名与主站一致，聊天表会在该库中自动创建。

## 五、IIS 部署

### 5.1 一键脚本（推荐）

```powershell
# 以「管理员身份」打开 PowerShell 后执行
powershell -ExecutionPolicy Bypass -File F:\源代码\WaterCloud-3.x\deploy\iis\deploy-iis.ps1 `
    -SiteName WaterCloud -Port 8080 -PhysicalPath "F:\源代码\WaterCloud-3.x\deploy\publish" -AppPool WaterCloudPool
```

脚本会自动完成：安装 Hosting Bundle（未安装时）→ 创建无托管代码的应用程序池 → 创建站点 → 授予 `IIS_IUSRS` 与应用程序池标识修改权限 → 添加防火墙端口 → 重启应用程序池。

日志写入 `deploy/iis/deploy-iis.log`。

### 5.2 手动部署要点

1. 安装 IIS 与 Hosting Bundle，确认 `%windir%\System32\inetsrv\aspnetcorev2.dll` 存在。
2. 新建应用程序池：**.NET CLR 版本 = 无托管代码**，托管管道 = 集成。
3. 新建站点，物理路径指向 `deploy/publish`，端口如 `8080`。
4. 站点根已包含 `web.config`（发布时自动生成），关键内容：

```xml
<system.webServer>
  <handlers>
    <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
  </handlers>
  <aspNetCore processPath="dotnet" arguments=".\WaterCloud.Web.dll"
              stdoutLogEnabled="false" stdoutLogFile=".\logs\stdout" hostingModel="inprocess" />
</system.webServer>
```

5. 目录权限：`IIS_IUSRS` 与 `IIS AppPool\WaterCloudPool` 需对站点目录有 **修改** 权限（上传附件、写入 DataProtection 密钥、SQLite 文件都需要）。
6. 防火墙放行端口：`New-NetFirewallRule -DisplayName "WaterCloud 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow`

> `inprocess` 托管时 IIS 会自行分配端口，`appsettings.json` 中的 `urls` 不生效，因此发布配置里已移除该项（避免与 Kestrel 端口冲突）。

## 六、Nginx 部署

Nginx 不做进程托管，需要一个常驻的 Kestrel 进程作为后端。

```powershell
# 1) 启动 Kestrel（框架依赖，需要 ASP.NET Core Runtime 6）
Start-Process dotnet -ArgumentList "WaterCloud.Web.dll","--urls","http://127.0.0.1:5005" `
    -WorkingDirectory "F:\源代码\WaterCloud-3.x\deploy\publish" -WindowStyle Hidden

# 2) 校验并启动 Nginx
Set-Location "F:\源代码\WaterCloud-3.x\deploy\nginx"
.\nginx.exe -t
.\nginx.exe
```

`nginx/conf/nginx.conf` 关键配置：

```nginx
upstream watercloud_kestrel { server 127.0.0.1:5005; }

server {
    listen       8081;
    server_name  localhost;
    client_max_body_size 200m;      # 作业/课件上传

    location / {
        proxy_pass         http://watercloud_kestrel;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_set_header   Upgrade           $http_upgrade;   # SignalR / WebSocket
        proxy_set_header   Connection        "upgrade";
        proxy_read_timeout 300s;
        proxy_buffering    off;
    }
}
```

常用命令：

```powershell
.\nginx.exe -t              # 校验配置
.\nginx.exe -s reload       # 平滑重载
.\nginx.exe -s stop         # 停止
```

> 开机自启：把上面的启动命令做成任务计划（触发器=开机），或使用 NSSM 将 `nginx.exe`、`dotnet WaterCloud.Web.dll` 注册为 Windows 服务。
> 注意 Kestrel 的监听地址必须与 `proxy_pass` 一致；若要对外网访问，把 Kestrel 绑定改为 `http://*:5005` 仅在 Nginx 前面时使用，且建议只绑定内网地址。

## 七、聊天服务（LayIM）部署

聊天系统是**独立进程**，不随主站启动；主站右下角聊天图标依赖它，未启动时图标不会出现（不影响其他功能）。

```powershell
Start-Process dotnet -ArgumentList "LayimChat.dll" `
    -WorkingDirectory "F:\源代码\WaterCloud-3.x\deploy\publish-chat" -WindowStyle Hidden
```

- 默认监听 `http://localhost:5301`（`publish-chat/appsettings.json` 的 `Urls`）。
- 主站 `appsettings.json` 的 `Chat.BaseUrl` 必须与之一致。
- `Chat.SsoSecret` 必须与聊天服务 `Integration:SsoSecret` 完全相同，否则单点登录失败。
- 聊天服务与主站共用同一个数据库：用户读 `sys_user`、组织读 `sys_organize`，其余 `chat_*` 表首次启动自动创建。

## 八、发布到远程服务器的标准流程

1. **准备程序文件**：把 `deploy/publish`（IIS 或 Kestrel）与 `deploy/publish-chat`（聊天）复制到服务器，例如 `D:\WaterCloud\publish`。
2. **安装运行时**：IIS 方式装 `Hosting Bundle 6.0.28`；Nginx 方式装 `ASP.NET Core Runtime 6.0`；聊天服务装 `ASP.NET Core Runtime 8.0`。
3. **初始化数据库**：按第四章导入对应数据库文件。
4. **修改配置**：编辑 `publish/appsettings.json`
   - `DBProvider`、`DBConnectionString` 指向服务器数据库；
   - `Chat.BaseUrl` 改为聊天服务实际地址；
   - `AllowedHosts`、`SystemConfig.AllowCorsSite` 改成服务器域名；
   - `AMap.Key` 填入高德 Web 端 JS API 密钥（打卡地点选择需要）。
5. **部署站点**：IIS 执行 `deploy-iis.ps1`（可用参数改站点名与端口）；Nginx 复制 `nginx` 目录并改 `listen` 端口与 `proxy_pass`。
6. **开放端口**：IIS 站点端口、聊天服务端口（如 5301）加入防火墙入站规则。
7. **启动并验证**：打开 `/Login` 登录，检查菜单、上传、聊天图标、定时任务是否正常。
8. **改密码**：上线后立即修改 `admin` 等账号密码（系统管理 → 用户管理）。

## 九、常见问题（FAQ）

| 现象 | 原因与处理 |
| --- | --- |
| IIS 返回 **500.31 / 502.5** | 未安装 Hosting Bundle，或运行时版本与站点不匹配（本项目为 .NET 6）。装 6.0.x Hosting Bundle 后 `iisreset` |
| IIS 返回 **500.19**（配置错误） | 应用程序池不是「无托管代码」，或站点目录缺少 `web.config` |
| Nginx 返回 **502 Bad Gateway** | Kestrel 未启动 / 端口不一致 / 被防火墙拦截。先直接访问 `http://127.0.0.1:5005/Login` 验证 |
| 页面无样式、JS 不生效 | 站点根不是发布目录（`wwwroot` 未发布）；或浏览器缓存，改 `ProjectVersion` 后强刷（Ctrl+F5） |
| 登录提示 **IP 已被锁定** | 连续输错密码触发 `sys_filterip` 黑名单（默认封禁 12 小时）。等待、或删除该表对应记录、或重启站点清空失败计数 |
| 密码正确仍无法登录 | 密码校验算法为 `md5(DES(md5(明文,32).小写, F_UserSecretkey).小写, 32)`，改写数据库密码必须用同一算法；正常应通过界面重置 |
| 上传附件失败 | 站点目录缺少写权限（`IIS_IUSRS`、应用程序池标识需「修改」权限） |
| 聊天图标不显示 | 聊天服务未启动（5301），或主站 `Chat.BaseUrl` 与之不一致 |
| 切换数据库后启动报错 | 连接串错误 / 库未初始化 / 服务未启动；空库首次启动可临时 `AutoCreateTable=true`，建表后改回 `false`；MySQL 需 `utf8mb4`，PostgreSQL 标识符小写 |
| SQLite 出现 `database is locked` | SQLite 单写者限制，降低并发或改用 SQL Server / MySQL / PostgreSQL |
| 定时任务重复执行 | `OpenQuartz=true` 且多实例部署时，需要 `IsCluster=true` 并配置共享数据库 |
| 打卡地图不显示 | `appsettings.json` → `AMap.Key` 未配置（申请高德「Web 端(JS API)」密钥后重启站点） |
